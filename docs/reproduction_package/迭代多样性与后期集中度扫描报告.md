# 三领域迭代多样性与后期集中度扫描报告

## 结论先行

本次扫描**没有发现明显的题目多样性坍缩**：三个领域的后期样本仍覆盖原有知识点，题目文本没有出现高比例近重复，且迭代后期的平均最近邻相似度均低于 0.15（按去除停用词后的词集合 Jaccard 相似度计算）。

但发现了一个需要记录的现象：**低分样本在后期向少数困难知识点集中**。这更像是自适应搜索成功锁定弱点，而不是题目生成器只会重复同一个模板。

从更高一层看，用户的直觉是对的：虽然数学、代码和 Instruction 的题面不同，后期的**陷阱机制正在趋同**。它们共同围绕“主任务做对了，但附加约束/边界条件漏掉了”这一类失败模式。

| 跨领域共同陷阱 | Instruction | Math | Code |
|---|---|---|---|
| 多个条件必须同时满足 | 句数、词数、禁词、语气一起限制 | 求解、证明、定义域或参数条件一起要求 | 功能、类型、顺序、异常处理一起要求 |
| 精确性/格式约束 | Markdown 对齐、JSON 转义、固定词序 | 最终形式、整数系数、完整分类 | 纯代码、返回结构、输入不变性 |
| 边界与隐藏前提 | 不能出现某字母、不能直接说情绪 | 除数不为零、重根判定、模数分解 | 空输入、重复边、自环、坏文件、引号转义 |
| 局部正确但整体不合格 | 内容符合语义但漏一条格式规则 | 计算步骤大体正确但漏定义域/特殊解 | 正常样例能跑但边界测试失败 |

因此，应该区分两件事：**题目内容没有明显坍缩，但失败模式存在“机制级收敛”**。这符合自适应弱点搜索的预期：系统不断发现模型最脆弱的共同能力——同时维护许多约束，并在边界条件下保持严格正确。

## 扫描方法

- instruction：80 条完整实验日志，seed 32 条，adaptive 1/2/3 各 16 条。
- math：40 条扩展日志，seed 20 条，adaptive 1/2 各 10 条。
- code：34 条有效扩展日志，seed 18 条，adaptive 1/2 各 8 条。
- 检查维度：每轮知识点覆盖、评分低于 4 的比例、题目重复、去停用词词集合相似度、后期高频短语。
- 相似度是筛查指标，不是语义等价判定；代码题天然共享 “Write a Python function” 等任务格式，因此同时看了去除通用词后的结果。

## 风险判断

### 未发现的风险

- 没有某一轮只剩一个知识点。
- 没有样本对达到 0.5 以上的去停用词词汇相似度。
- 没有明显的完全重复题目。
- Math 和 Code 后期仍保留跨子领域覆盖。

### 需要关注的风险

- Code 的低分比例在 adaptive 2 上升到 62.5%，且多个困难点各只有 1 条样本；这说明搜索偏向困难边界条件，但当前样本数不足以判断每个知识点的稳定失败率。
- Instruction 的低分率后期上升到 75%，不过它依然均匀覆盖 16 个知识点；这更符合弱点搜索目标，而不是多样性丢失。
- 代码题的通用句式 `Write a Python function` 高频出现，这是任务格式造成的表面重复；评估时应关注函数语义、边界条件和数据结构要求，而不是该固定前缀。

## 建议

如果继续扩展，建议每个知识点至少采样 5–10 条，并增加一个“去重门槛”：新题目与历史题目的去停用词相似度超过 0.5 时拒绝或重新生成。同时按知识点分别报告 ISR 的置信区间，避免把单条后期低分误读成稳定坍缩。
