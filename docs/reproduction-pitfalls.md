# AutoDetect Reproduction Pitfalls

This log distinguishes problems observed during this reproduction from risks
found by inspecting the released implementation. It is updated after every live
stage so that workarounds and their effect on comparability remain auditable.

| Date | Evidence | Stage | Symptom | Cause | Resolution | Impact | Prevention |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 2026-09-28 | Code inspection | Initial review | The released task scripts cannot run without editing source placeholders and loading a local CUDA model. | API URL/key, GPT model names, `cuda:0`, and model paths are hard-coded in each monolithic script. | Added a shared YAML configuration, environment-only credential loading, and SiliconFlow clients for both agent and target models. | Model substitutions make this a directional reproduction rather than an exact numerical replication; no GPU is required. | Keep provider/model/path choices in validated configuration and reject credentials in tracked files. |
| 2026-09-28 | Code inspection | Initial review | A persistent API or parsing failure can keep retrying and spend unexpectedly. | Released generation functions retry up to 50 times, while some search loops retry indefinitely when malformed output prevents progress. | Limited each request to four attempts, added timeouts and a total sample cap, and checkpoint every completed attempt. | Transient failures may leave explicit missing samples instead of silently retrying until success. | Require bounded retries, hard caps, and visible failed-sample denominators. |
| 2026-09-28 | Code inspection | Initial review | Valid model output can fail parsing unless it uses one exact fenced-JSON shape; malformed judge output can also crash late. | Released code relies on a narrow regular expression and takes the final bracket match without structured validation. | Added balanced-brace JSON extraction, final-object selection, finite score validation in the 1–10 range, and one schema-aware repair request. | Parsing behavior is more robust than the released code, but generated content and scoring rubric remain comparable. | Test plain JSON, fenced JSON, nested braces, reasoning text, missing scores, and out-of-range scores offline. |
| 2026-09-28 | Code inspection | Result aggregation | `count_res.py` fails while writing the final summary. | The released script passes `intend=4` instead of `indent=4` to `json.dump`. | Replaced the aggregator with tested CSV/Markdown reporting from append-only checkpoints. | Output format differs from the released script, while ISR keeps the paper's `score < 4` definition. | Exercise report generation in the offline suite and regenerate it without network access. |
| 2026-09-28 | Observed | API connectivity smoke | DeepSeek-V4-Flash returned reasoning/final delimiters mixed into content, such as duplicated text around a closing think tag. | The provider can expose reasoning markers in the normal content field for this model. | Select the last complete JSON object or final bracketed score and handle balanced reasoning sections defensively. | Without this handling, valid calls would be mislabeled as failures and inflate cost through retries. | Keep regression fixtures for balanced and stray reasoning delimiters. |
| 2026-09-28 | Observed | Server initialization | The system volume had about 22 GB free while the data volume had about 1.1 TB free. | The shared server's root filesystem is already heavily utilized. | Put source, environments, caches, temporary files, and outputs below `/data/liuxingtong`. | Avoids increasing pressure on the system volume; the shared data volume still needs monitoring. | Export cache/temp paths before installation and check `df -h /data` before larger follow-up experiments. |
| 2026-09-29 | Observed | Repository setup | Direct GitHub clone from the server produced no progress for more than a minute on two attempts. | The server-to-GitHub route was slow or stalled; repository size was not the limiting factor after blob filtering. | Cloned in the task workspace and synchronized the exact Git checkout to `/data/liuxingtong/src/AutoDetect` with rsync. | Setup took longer but did not change source history or experiment behavior. | Verify local and remote commit hashes after every synchronization. |
| 2026-09-29 | Observed | Offline test setup | Calling the virtual environment's `pytest` launcher could not import the repository package, while `python -m pytest` could. | The released repository has no package metadata and the launcher did not put the checkout root on `sys.path`. | Added `pytest.ini` with `pythonpath = .` and retained a Python 3.8 server test as the compatibility authority. | Test invocation is now portable without installing the repository as a package. | Keep the exact launcher command in CI/server verification and avoid ad-hoc `PYTHONPATH` exports. |

## Update rule

For each new live issue, add one row with evidence, the smallest supported root
cause, the applied workaround, and whether it changes cost, runtime,
comparability, or the experiment's conclusion. Do not convert a hypothesis into
an observed fact without logs or a reproducible symptom.
