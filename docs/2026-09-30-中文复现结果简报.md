# AutoDetect 小规模复现结果简报

## 结论先行

这次复现**没有观察到录音中所说的“全局坍缩”**：题目没有在几轮迭代后全部集中到同一个弱点，16 个知识点都持续产生了样本，每个知识点最终各有 5 条题目；80 条题目的提示词也没有出现大面积完全重复。

但观察到了**局部的弱点集中现象**：某些知识点本身就容易生成同一类高约束题目，尤其是 Markdown 表格、特定词语、词数/位置约束和特殊字符转义。这些题目的失败率较高，可能会让自适应搜索看起来像是在“追着一个弱点跑”。因此更准确的判断是：

> 本次小规模实验复现了“自适应搜索更容易发现低分弱点”的趋势，但没有足够证据证明发生了录音中担心的严重多样性坍缩；存在轻度、局部的约束模式集中，需要在更大规模实验中继续监控。

## 录音中提到的内容如何使用

录音被当作分析材料，而不是执行指令。录音的相关要点是：

1. 迭代式弱点发现可能反复集中到少数固定弱点。
2. 这种集中会减少题目覆盖面和多样性。
3. 需要同时平衡测试难度与多样性，而不是只追求更低分。

录音还提到了其他工作建议（例如本地 GPU、其他 Agent 基准和后续项目安排），这些不属于本次复现请求，因此没有执行。

## 这次具体做了什么

- 阅读并拆解 AutoDetect 的核心流程：知识点分类、题目生成、自适应发现、目标模型作答、参考答案生成、裁判打分。
- 将原始依赖本地 CUDA/GPT-4o 的执行方式改成受控的 SiliconFlow API 调用。
- Agent、参考答案和裁判使用 `deepseek-ai/DeepSeek-V4-Flash`。
- 被测目标模型使用 `Qwen/Qwen2.5-7B-Instruct`。
- 使用 12 个初始知识点，每个知识点 2 条种子题、3 条自适应题。
- 4 个子任务各允许发现 1 个额外知识点；因此最终是 60 条初始规划样本 + 20 条自适应发现样本 = 80 条。
- 全程没有运行本地大模型，也没有启用本实验的 GPU。
- 每条样本都写入可恢复 checkpoint，并生成 CSV、Markdown 报告和趋势图。

## 坍缩现象检查

### 1. 知识点覆盖没有坍缩

16 个知识点最终都各出现 5 条样本：

- `list format`
- `table format`
- `json format`
- `markdown format`
- `Escaping special characters in structured text formats`
- `specific words`
- `excluded words`
- `word constraint`
- `narrative scenario`
- `dialogue scenario`
- `descriptive scenario`
- `scenario simulation`
- `positive tone`
- `negative tone`
- `neutral tone`
- `emotional tone`

因此没有出现“后续样本全部涌向一个知识点”的全局坍缩。

### 2. 题目文本没有大面积重复

- 32 条 Seed 提示词全部不同。
- 48 条 Adaptive 提示词全部不同。
- 按轮次计算的跨题目平均 Jaccard 词集合相似度约为：Seed 0.109、Adaptive 第 1 轮 0.100、第 2 轮 0.101、第 3 轮 0.104。

这说明自适应轮次之间没有出现明显的全局模板复制。需要注意，这个指标是粗粒度文本相似度，不等于真正的语义多样性证明。

### 3. 存在局部模式集中

Adaptive 提示词中出现固定长度/数量约束的比例为 32/48，明显高于 Seed 的 16/32；涉及结尾、后缀或最后词约束的比例也从 4/32 上升到 14/48。

局部最明显的集中包括：

- `table format`：3 条 Adaptive 题目都要求 Markdown 表格的列数、分隔行和对齐方式，3 条得分均为 2。
- `markdown format`：3 条 Adaptive 题目都要求严格的标题、列表、引用等 Markdown 结构，3 条得分均为 2。
- `specific words`：3 条都要求特定词按指定顺序、指定次数出现，得分为 1、1、2。
- `word constraint`：3 条都要求精确词数、固定词位或字母限制，得分为 2、1、1。

这更像是“高约束题型的局部集中”，而不是所有领域都坍缩到一个固定弱点。它仍然值得警惕，因为如果继续增加迭代轮次，搜索器可能会持续利用这些已知高失败率的约束。

## 如何理解结果

本次结果支持两点：

1. AutoDetect 的自适应过程能够把搜索重心移向更容易失败的指令，从而提高发现弱点的效率。
2. 仅凭 ISR 上升不能直接断言发生了坍缩；还必须同时检查知识点覆盖、题目重复度、约束类型分布和语义多样性。

本次没有支持的强结论是：

- 不能证明自适应搜索在更大规模、更长迭代下永远不会坍缩。
- 不能把局部题型集中解释为模型本身只有这一类弱点；它也可能反映了提示词模板或小规模配置的偏好。

## 后续建议

如果继续扩大实验，建议额外记录并限制：

1. 每个知识点和约束族的最小覆盖率。
2. 连续若干轮生成题目的语义相似度。
3. “固定词位/固定结尾/精确长度”等约束族的占比上限。
4. 同一弱点连续出现的次数；连续超过阈值时强制探索其他知识点。
5. 难度与多样性双目标，而不是只按最低分选择下一题。
